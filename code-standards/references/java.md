# Java 开发规则

本规则将 Google Java Style 的格式与命名默认值，同《阿里巴巴 Java 开发手册（黄山版，2022）》衍生的 Java/JVM 约束结合。先阅读[公共工程规则](core-engineering.md)，并将本规则应用于新增或修改的 Java 代码；服务端任务另读[后端工程规则](backend-engineering.md)。

仓库指令、格式化器/静态检查配置和既有局部约定始终优先。没有声明风格的新 Java 项目采用 Google Java Style；下方黄山版衍生规则只保留与 Java 类型、集合、并发、异常、日志和测试直接相关的内容。

## 1. 规则等级与范围

- `必须`/`禁止`：除非更高优先级的项目规则覆盖，否则将修改代码中的违反项视为阻断问题。
- `应当`/`不应`：默认遵守；只有明确记录的项目特定理由才能偏离。
- 将改动限制在任务范围内，不为一个聚焦任务改造整个仓库。
- 遵守生成代码的所有权边界，修改生成器或 Schema，不手工编辑生成文件。

## 2. 命名与格式

- 普通源文件按以下顺序组织：license/copyright（如有）、package、import、唯一顶层类型；存在的各部分之间恰好空一行。
- 每个普通源文件必须有 package 声明；`package-info.java` 和 `module-info.java` 按其专门结构处理。package 和 import 不换行，也不受 100 列限制。
- `module-info.java` 中按 `requires`、`exports`、`opens`、`uses`、`provides` 分组，各非空组之间空一行。
- 源码只使用 ASCII 普通空格作为空白；特殊字符优先标准转义，可打印非 ASCII 字符根据可读性选择原文或 Unicode 转义并在必要时解释。
- 类、接口和枚举必须使用 `UpperCamelCase`；方法、参数、字段和局部变量使用 `lowerCamelCase`；常量使用描述性的 `UPPER_SNAKE_CASE`。
- 包名必须使用小写英文；禁止中英文、拼音和英文混用，禁止晦涩缩写，标识符不得以 `_` 或 `$` 开头或结尾。
- 抽象类应以 `Abstract` 或 `Base` 开头，异常类以 `Exception` 结尾；测试按被测对象命名，并服从仓库约定。
- 避免父子类型之间令人混淆的字段遮蔽。布尔 POJO 属性不得使用 `is` 前缀；数据库 `is_xxx` 列应显式映射到 Java 属性 `xxx`。
- 将业务魔法值替换为具名常量或枚举；含义明显的测试字面量可保留在局部。
- `long`、`float`、`double` 字面量后缀必须使用大写 `L`、`F`、`D`。
- 使用 UTF-8、Unix 换行且不使用 Tab；无项目规则时采用两空格块缩进和 100 列限制。
- 禁止通配符 import。静态 import 置于非静态 import 之前，每行一个，并按 Google Java Style 排序；仓库格式化器另有规定时从其规定。
- 每行只写一条语句。每个源文件应只有一个顶层类型，并以该类型命名文件。
- 同名重载方法和构造器必须连续放置，中间不插入其他成员；其余成员按维护者能解释的逻辑顺序组织，不按新增时间堆放。
- `if`、`else`、`for`、`while`、`do` 即使只有一条语句也必须使用大括号。
- 非空 block 使用 K&R 大括号；右大括号只有在结束语句、方法、构造器或具名类型时才换行，`else`/`catch`/`finally` 与其同行。
- 空 block 可写 `{}` 或标准多行形式；`if/else`、`try/catch/finally` 等多块语句中的空 block 不得压成难读形式。
- 行超过 100 列时优先在更高语法层级断行；continuation 至少增加四空格，但不与块缩进混淆。必要时提取局部变量或方法，而不是制造复杂对齐。
- package、import、文本块内容、可复制的长命令和无法合理拆分的 URL/标识符可按 Google 规则超过列宽。
- 一次只声明一个变量；除常规 `for` 初始化外，不使用 C 风格多变量声明。
- modifier 使用 Java Language Specification 推荐顺序；annotation 每个一行或按项目 formatter 合理放置，不在同一位置混乱堆叠。
- array bracket 属于类型而不是变量名；array initializer 可按 block-like 结构换行并使用允许的尾随逗号。
- switch case 在 switch block 内按 Google 规则缩进；非空 switch 必须清晰处理每个 case、default 或穷尽 enum。
- Javadoc 使用 `/** ... */`，摘要完整描述契约；公共类型和成员通常提供文档，显而易见的 override 可通过 `{@inheritDoc}` 或项目策略避免重复。
- Javadoc 的 `@param`、`@return`、`@throws` 与实际签名和行为一致；不要只重复参数名，也不要记录已失效异常。
- 将 Checkstyle、Spotless、EditorConfig 和仓库格式化器视为格式规范的事实来源。

## 3. 类型、对象、金额与时间

- 重写方法必须添加 `@Override`；静态成员通过声明它的类型访问。
- 禁止 finalizer；资源必须通过 `AutoCloseable`、try-with-resources 或明确生命周期管理。
- `var` 仅在项目版本允许且 initializer 使类型与语义清晰时使用；不得隐藏数值宽度、领域类型或重要泛型信息。
- lambda 适合短小行为；复杂分支、需要文档或复用时提取具名方法。不要依赖含义不清的参数名和隐式捕获。
- Optional 主要用于返回值；不作为字段、参数或序列化模型的通用 null 替代，除非项目契约明确。
- 未完成兼容性分析时，禁止引入已弃用 API 或修改公共签名。
- 对象比较使用已知非空的接收方或 `Objects.equals`；包装类型不得使用 `==` 比较值。
- 业务数值不得直接比较浮点相等，使用领域容差或 `BigDecimal`。
- 禁止调用 `new BigDecimal(double)`；使用字符串构造器或 `BigDecimal.valueOf`。数值相等用 `compareTo`，仅在 scale 属于契约时用 `equals`。
- 金额不得使用 `float` 或 `double`；使用最小货币单位整数或明确精度和舍入规则的 `BigDecimal`。
- 持久化 Java 类型必须与数据库语义和范围一致；数据传输或持久化对象中不得隐藏业务默认值。
- 构造方法不得执行 I/O、远程调用或复杂业务流程。
- 避免 `Object...`；仅对类型和业务含义一致的值使用可变参数。
- 兼容的序列化类型变更应保持 `serialVersionUID`；不兼容变更必须明确记录。
- `toString` 不得泄露凭据或个人数据。
- 优先使用 `java.time`；除无法避免的适配边界外，不新增 `java.sql.Date`、`Time` 或 `Timestamp`。
- 区分年/月/分钟以及 24/12 小时格式；时区和 Locale 影响行为时必须显式指定。
- 不将 365 天硬编码为一年；耗时测量使用单调时钟，当前时间使用可注入 `Clock` 或项目时间抽象以便测试。
- 不共享非线程安全的日期格式化器，优先使用 `DateTimeFormatter`。

## 4. 集合与 Stream

- `equals` 与 `hashCode` 必须同时重写；对象存入 Set 或作为 Map key 期间，参与两者计算的字段必须保持稳定。
- 判空应使用 `isEmpty()`，并按项目策略处理可能的 `null`。
- `Collectors.toMap` 必须指定重复 key 合并策略并确保 value 非空；顺序重要时指定 Map supplier。
- 集合转数组必须类型安全；禁止将 `subList` 转成 `ArrayList`，禁止修改不可变集合。
- 将 `Arrays.asList` 视为定长集合；增删前复制为新的可变集合。
- 增强 `for` 循环中不得结构性修改集合；使用 `Iterator`、`removeIf` 或构造新结果。
- 注意 `subList` 共享底层存储，`keySet`/`values`/`entrySet` 是 Map 的实时视图。
- Comparator 必须满足反对称、传递和一致性，优先使用 Comparator 组合方法。
- 除既有契约另有要求外，返回空集合而不是 `null`。

## 5. 并发

- 单例状态和方法必须线程安全；共享可变状态必须有明确的所有权和同步模型。
- 不直接创建应用工作线程，使用受管 Executor、框架调度器或项目并发抽象。
- 生产线程池不得使用无界 `Executors` 工厂；通过 `ThreadPoolExecutor` 或项目封装明确核心/最大线程数、有界队列、命名工厂、拒绝策略和关闭生命周期。
- 线程和线程池必须有可诊断名称，并可靠关闭资源。
- 尤其在线程池中，必须在 `finally` 调用 `ThreadLocal.remove()`。
- 缩小锁范围；多个资源按固定顺序加锁；仅在成功获得且当前线程持有锁时解锁。
- 并发写入必须确定防丢失更新策略：乐观版本、数据库锁、分布式锁或原子更新。
- 定时任务失败应隔离并记录，防止一次异常静默取消后续执行。

## 6. 控制流与可读性

- 每个 `switch` 分支必须终止，或说明有意 fall-through；外部输入用于 switch 前处理 `null`；版本支持时优先现代 switch 表达式。
- 三元表达式仅用于短且类型清晰的表达式，避免嵌套以及数值提升或拆箱歧义。
- 并发或重试循环不得依赖计数器恰好等于某值才退出，应使用范围、上限、超时和取消。
- 方法保持单一职责，提取领域谓词，使用提前返回并减少深层嵌套。
- 重复使用的正则表达式应预编译；不可信模式应评估灾难性回溯风险。

## 7. 异常与日志

- 注释用于解释意图和不明显约束，并随行为同步更新；公共 API、抽象方法和复杂边界应编写 Javadoc。
- 不用异常实现正常控制流；禁止空 catch、吞掉失败或无增益地捕获后重抛。
- 可行时使用 try-with-resources；禁止从 `finally` 返回；捕获异常时保持事务回滚语义。
- 在稳定边界转换异常；除合理的框架或任务顶层边界外不捕获 `Throwable`；不得吞掉 `Error` 或线程中断，应恢复中断标记或按契约传播。
- 使用 SLF4J 或仓库日志门面；生产代码禁止 `System.out`、`System.err` 和 `printStackTrace`。
- 使用参数化日志，在合适边界只记录一次可执行上下文和堆栈，避免各层重复记录。
- 禁止记录密码、令牌、密钥、完整证件/支付标识、Cookie、会话标识或未脱敏个人数据。
- 不为日志将大型或敏感对象整体序列化为 JSON；热路径避免昂贵的日志参数计算。

## 8. 测试

- 行为变化必须新增或更新测试；修复缺陷时应先添加能复现问题的回归测试。
- 单元测试必须自动、可重复、独立、无交互，不依赖执行顺序、真实时间、实时网络和共享外部状态。
- 构建未声明其他布局时，单元测试放在 `src/test/java`，资源放在 `src/test/resources`。
- 按风险覆盖正常路径、边界、null、失败路径和关键不变量。
- 不删除测试、不弱化断言、不扩大 ignore，也不通过重试掩盖失败。
- 使用固定 Clock、受控随机源、测试替身、隔离集成数据和可靠清理。

## 9. 验证清单

- 先运行最小相关测试，再运行受影响模块的常规测试、静态检查和构建命令。
- 对并发、资源生命周期、序列化、反射和依赖变更增加针对性 Java/JVM 验证；后端行为按[后端工程规则](backend-engineering.md)扩展。
- 检查最终 diff 中的调试输出、密钥、临时文件、无关格式化、意外生成文件和范围膨胀。
- 报告准确命令与结果，明确标注未运行检查、阻碍、假设和剩余风险。
