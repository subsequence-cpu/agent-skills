# 后端工程规则

本规则适用于服务端 API、认证授权、持久化、事务、缓存、消息、后台任务、外部集成、可靠性和可观测性。先读取[公共工程规则](core-engineering.md)，再读取任务涉及的语言和数据格式规则。

这些规则是跨语言的工程判断，不替代仓库已有架构、协议、数据治理、SLO、部署平台和运维流程。只有修改相应边界时才应用对应章节。

## 服务边界与 API

- 遵循现有模块和服务边界，分离协议适配、应用编排、领域规则和持久化；不要为小改动创建无真实所有权的新层。
- API 明确认证方式、请求与响应模型、状态码、错误模型、幂等性、分页、版本和兼容策略。
- HTTP 方法、缓存、条件请求和重试语义遵循协议；不能仅凭路径命名推断安全性或幂等性。
- 对外契约使用 OpenAPI、Schema、IDL 或仓库等价机制表达，并使实现、生成客户端、示例和文档保持同步。
- 错误响应稳定、可搜索且不泄露堆栈、SQL、路径、主机或原始内部异常；内部诊断通过关联标识连接日志和追踪。
- 列表、分页和排序必须确定且有边界；大结果使用流式、游标或批处理，而不是无限制装入内存。

## 输入、身份与授权

- 在服务边界验证类型、长度、范围、格式、编码和跨字段不变量；解析成功不代表输入可信。
- 认证确认主体，授权同时验证操作和目标对象；不得只依赖前端隐藏、路由守卫或可猜测标识符。
- 高成本或有状态操作根据风险提供幂等、防重放、限流、配额和审计能力。
- 文件、URL、模板、表达式和命令输入必须限制协议、目标、路径、大小和内容，防止注入、路径穿越、SSRF 与资源耗尽。
- 凭据、令牌、会话标识、个人数据和完整敏感载荷不得进入普通日志、错误响应、指标标签或追踪属性。
- 密码学、密码存储、token 验证和随机数使用经维护的标准库或项目安全组件，不自行设计协议。

## 数据、事务与演进

- 数据模型明确标识、唯一性、可空性、单位、精度、时区、生命周期和删除策略；命名服从现有 Schema 约定。
- 事务边界围绕业务不变量，保持短小；远程调用和长计算通常不放入数据库事务。
- 数据库写入考虑并发更新、重复请求和重放，按场景使用原子更新、唯一约束、乐观版本、锁或幂等记录。
- Schema 变更必须适应滚动发布和旧版本实例；破坏性变更采用扩展、迁移、切换、清理等可回退阶段。
- 查询显式表达需要的列和稳定排序；索引根据真实查询与基数设计，并用执行计划或测量验证，而不是机械限制 JOIN 数量。
- 精确金额和计量值使用明确精度与舍入规则；时间保存清晰时区语义，展示转换留在系统边界。
- 数据修正、批量更新或删除先用等价查询预览范围并确认影响；未经授权只生成可审查脚本，不操作真实环境。
- ORM、查询构造器和数据库驱动必须使用参数绑定；原始替换或动态标识符只能来自受控 allowlist。

## 异步、消息与可靠性

- 每个远程调用设置连接、读取和总超时，并传播取消；超时值来自上游预算和实际延迟分布。
- 只自动重试幂等操作或受幂等键保护的写入；限制次数，使用退避和 jitter，并避免多层重试放大流量。
- 队列、线程池、连接池、批次和内存缓存必须有界，并定义过载时的拒绝、降级或背压行为。
- 消费者明确投递语义、确认时机、去重、顺序、毒消息和死信处理；不得假设“恰好一次”自动成立。
- 定时任务和后台作业具有唯一执行、超时、取消、失败隔离、重跑和可诊断状态。
- 服务关闭时停止接收新工作、等待或转移在途任务并释放资源；健康检查区分进程存活与是否可接收流量。
- 熔断、缓存、降级和补偿只用于明确的失败模式，并记录一致性、陈旧数据和恢复策略。

## 可观测性与运行配置

- 日志使用结构化字段和稳定事件名称，在合适边界记录一次可执行上下文；避免各层重复记录同一异常。
- 指标名称、单位和 label 保持稳定且有界；用户 ID、请求 ID、原始 URL 等高基数值不作为普通指标标签。
- trace 和关联标识跨进程传播，但只接收受信或经过清理的上下文；关键入口、出口和队列边界保留因果关系。
- 为关键服务定义可观察的可用性、延迟、错误和容量信号；告警面向可执行症状，不为每条日志制造告警。
- 配置在启动时验证；secret 由批准的密钥系统提供，不进入镜像、仓库、命令行或诊断转储。
- feature flag、灰度和兼容开关必须有所有者、默认值、观测方式和清理条件，不能成为永久分支。

## 依赖、发布与兼容性

- 依赖变更检查传递解析、重复版本、许可证、漏洞、制品大小和运行时兼容性；生产版本不得依赖临时快照制品。
- 协议、事件、数据库和配置变更支持部署顺序中的新旧版本共存；消费者应按契约处理未知可选字段。
- 发布前验证迁移、回滚和数据兼容路径；无法安全回滚的数据变更必须明确恢复方案。
- 容器和进程使用最小权限、确定的资源限制和只读边界；临时文件、端口和信号处理遵循部署平台约定。

## 测试与验证

- 单元测试覆盖领域规则和失败路径；契约测试覆盖 API、事件和序列化兼容性。
- 对数据库、缓存、消息和第三方协议使用贴近真实实现的集成测试，同时隔离真实生产系统。
- 测试超时、取消、重复投递、并发更新、部分失败、依赖变慢、进程重启和迁移中的新旧版本共存。
- 性能或容量结论必须来自代表性数据与负载；检查延迟分位数、吞吐、资源、队列增长和恢复行为。
- 运行 formatter、静态检查、单元/集成测试、Schema/契约验证和构建；按风险扩大到安全、故障注入、迁移与负载验证。
