# 前端工程规则

本规则适用于浏览器中的用户界面、组件、路由、客户端状态、数据获取、资源构建、可访问性和 Web 性能。先读取[公共工程规则](core-engineering.md)，再读取任务涉及的语言、标记、样式和框架规则。

这些规则是跨框架的工程判断，不替代仓库已有架构、设计系统、浏览器支持矩阵、性能预算和测试策略。只有修改相应边界时才应用对应章节。

## 边界与架构

- 按页面、功能或领域组织代码，保持视图、状态、数据访问和基础设施依赖方向清晰。
- 组件只承担可解释的职责；展示组件不暗中执行远程写入，数据组件不包揽无关布局细节。
- 为状态指定唯一所有者。短生命周期交互保持局部；可分享、可恢复的导航状态优先进入 URL；服务端数据交给项目统一的数据获取与缓存层。
- 派生值从源状态计算，不保存可由其他状态可靠推导的副本；确需复制时明确同步时机和冲突策略。
- 跨页面共享状态、事件总线和全局 singleton 必须有真实需求，不以全局可变状态规避组件边界。
- 服务端渲染、预渲染和 hydration 必须保持输出确定；浏览器专用 API 放在明确的客户端生命周期中。

## 数据获取与异步交互

- 请求状态区分首次加载、后台刷新、空结果、部分结果、失败和离线，不用单个 boolean 混合不同语义。
- 组件销毁、参数变化或新请求取代旧请求时取消或忽略过期结果，防止竞态和卸载后更新。
- 去重、缓存、失效、重试和 optimistic update 使用项目统一机制，并定义失败回滚与最终一致性。
- 只对幂等或有幂等键保护的操作自动重试；限制次数，使用退避，并向用户提供可恢复路径。
- 表单提交防止重复动作，保留用户输入；字段错误、表单错误和系统错误分别呈现。
- API 类型不能替代运行时校验。对服务端、存储、URL 和第三方脚本产生的数据在边界验证。

## 语义、可访问性与国际化

- 优先原生 HTML 语义和控件；只有原生语义不足时才添加 ARIA，并实现对应键盘与焦点行为。
- 所有交互可用键盘完成，焦点顺序与视觉顺序一致；对话框、菜单和路由切换明确管理焦点。
- 表单控件具有可感知名称、帮助和错误关联；状态变化在需要时通过合适的 live region 通知。
- 不只依赖颜色、位置或动画传达信息；遵循设计系统的对比度、缩放、触摸目标和 reduced-motion 策略。
- 图片和媒体提供符合内容目的的替代文本、字幕或文本版本；装饰内容不制造读屏噪声。
- 用户可见文本、日期、数字、货币、复数和排序使用项目国际化机制，不在组件中拼接不可翻译句子。

## 浏览器安全与隐私

- 将 DOM、HTML、URL、CSS 和脚本视为不同输出上下文；依赖框架默认转义，不对不可信内容使用 raw HTML 或绕过安全机制。
- 客户端权限判断只控制体验，不作为授权边界；所有敏感操作仍由服务端验证身份、对象权限和业务约束。
- 认证凭据不放入 URL、日志或分析事件。浏览器存储不是可信安全边界；会话、Cookie、CSRF 和跨源策略服从项目设计。
- 第三方脚本、iframe、重定向和跨源消息必须限制来源与能力，并验证 `postMessage` 的 origin 和消息结构。
- 公共前端配置视为可被用户读取；构建时环境变量、source map 和静态资源中不得包含 secret。
- 埋点只收集必要数据，避免个人数据和高基数字段，并遵守同意、保留与删除策略。

## 性能与资源

- 先使用项目性能预算、真实用户数据和可重复的实验定位瓶颈，再引入 memoization、虚拟化或手工缓存。
- 控制首屏 JavaScript、CSS、字体和图片成本；按路由或功能延迟加载非关键资源，但避免产生请求瀑布。
- 为图片提供准确尺寸和响应式资源；为字体、关键 CSS 和预加载设置验证收益，避免布局偏移和长期阻塞。
- 减少主线程长任务、重复渲染和布局抖动；批量 DOM 读写，并将昂贵计算移出高频交互路径。
- 使用 Core Web Vitals 时同时查看真实用户与实验室数据，按项目目标和当前指标定义验收标准，不硬编码永久阈值。

## 构建、依赖与兼容性

- 以 lockfile、构建配置、`browserslist` 或等价配置和 CI 作为支持矩阵的事实来源。
- 新依赖必须说明用途，并检查维护状态、许可证、产物体积、tree-shaking、副作用、重复版本和浏览器兼容性。
- 不直接编辑生成 bundle、压缩文件、类型产物和资源清单；修改源文件或生成配置。
- 环境差异通过已验证配置表达；启动时尽早报告缺失配置，不在运行时静默采用危险默认值。
- 公共组件和 design token 变更保持可迁移性；避免在一次局部修改中引入第二套状态、样式或组件系统。

## 测试与验证

- 单元测试覆盖纯状态转换和边界逻辑；组件测试通过用户可感知的角色、名称和行为交互，不依赖脆弱 DOM 结构。
- 集成测试覆盖路由、数据获取、缓存失效、表单、权限显示和错误恢复；端到端测试聚焦关键用户旅程。
- 对视觉、主题、响应式、键盘、读屏和支持浏览器风险使用对应的视觉、可访问性和兼容性检查。
- 验证 loading、empty、error、offline、slow network、重复提交、请求乱序和组件销毁等状态。
- 运行项目 formatter、linter、类型检查、单元/组件/端到端测试和生产构建；按改动风险检查 bundle 与 Web 性能。
